# IRON HOOK Fishing Assistant

Первая рабочая версия помощника для Trout Area Fishing. React + TypeScript + Vite. Интерфейс на русском, тёмная тема, поддержка компьютеров и смартфонов. Платных сервисов и сервера базы данных нет.

## Как запустить на Windows

1. Установите **Node.js 24 LTS** с https://nodejs.org (npm устанавливается вместе с ним).
2. Скачайте проект и распакуйте его в папку, например `C:\IRON-HOOK`.
3. Откройте эту папку в Проводнике, наберите `cmd` в адресной строке и нажмите Enter.
4. Выполните по очереди:

```bat
npm ci
npm run dev
```

5. Откройте в браузере адрес, который напишет терминал (обычно `http://localhost:5173`). Оставляйте окно терминала открытым. Остановка: Ctrl+C. Повторный запуск: `npm run dev`.

### На смартфоне в той же домашней сети Wi-Fi

Запустите `npm run dev -- --host 0.0.0.0`. Узнайте IPv4 компьютера командой `ipconfig`. На телефоне откройте `http://IPv4-компьютера:5173`. При необходимости разрешите Node.js в брандмауэре Windows **только для частной сети**. Не открывайте порт на роутере. Это локальный доступ, не публикация в интернете.

## Что работает

- Главная панель с итогами и диаграммой количества рыб по приманкам.
- Добавление, изменение и удаление приманок; поиск; фото с устройства (до 2 МБ).
- Каталог снастей с редактируемыми характеристиками и готовые комплекты.
- Дневник тренировок и соревнований: дата, водоём, погода, 1–30 туров, несколько приманок и уловов в одном туре.
- Аналитика по приманкам, весам, цветам, турам и сравнение рыбалок.
- Скачивание JSON-копии данных и восстановление из файла с проверкой и подтверждением замены.

При первом запуске показаны **тестовые данные**, помеченные в интерфейсе. Они включены в общую статистику. Кнопка «Очистить базу» удаляет все записи после подтверждения. После очистки тестовые данные автоматически не возвращаются.

Рыбалка без уловов допустима. Средний улов = количество рыб / количество всех туров, включая нулевые. Диаграммы показывают улов в штуках, а не вероятность поклёвки или скорость ловли. Приманку, используемую в уловах, нельзя удалить; снасть, используемую в комплекте, тоже.

## Важно о сохранении

Данные и фотографии сохраняются в localStorage **конкретного браузера и адреса**. Между компьютером и телефоном они не синхронизируются. Очистка данных браузера удаляет дневник. Смена порта/адреса открывает отдельное хранилище. Не используйте приватный режим для постоянного дневника. Регулярно скачивайте резервную копию. Много крупных фотографий может заполнить хранилище — приложение сообщит об ошибке сохранения.

## Проверки и сборка

```bat
npm run build
npm run lint
npx playwright install chromium
npm test
```

`npm run build` создаёт готовые файлы в `dist`. Локальная проверка сборки: `npm run preview`. Автотесты проверяют формы, сохранение после обновления страницы, статистику, удаление и мобильную навигацию.

Публикация сайта выполняется владельцем через ручной запуск GitHub Actions. Для разработки используйте существующую папку проекта; отдельный Git worktree не нужен.

## Бесплатный сайт без установки программ: GitHub Pages

Подготовлен ручной сценарий `.github/workflows/pages.yml`. Он не публикует сайт при сохранении файлов или обычном push.

1. Загрузите весь исходный проект в ветку `main` репозитория `Roskorion/IRON-HOOK`, включая скрытую папку `.github`. Папки `node_modules` и `dist` загружать не нужно.
2. Для бесплатного GitHub Pages на GitHub Free репозиторий должен быть публичным. Не меняйте видимость, если не хотите открывать исходный код. Для закрытого репозитория выберите другой хостинг с подходящим бесплатным тарифом.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Когда будете готовы опубликовать приложение, откройте **Actions → Опубликовать IRON HOOK → Run workflow**, выберите `main` и подтвердите запуск. Если GitHub предложит включить Actions, включите их.
5. После успешного выполнения адрес появится в задаче `deploy` и в **Settings → Pages**. Для стандартной конфигурации этого репозитория ожидаемый адрес — `https://roskorion.github.io/IRON-HOOK/`; он заработает только после публикации.

На компьютере и телефоне приложение открывается обычным браузером. Node.js посетителям не нужен. После обновления кода повторите ручной запуск сценария.

Сам сайт будет общедоступным, без пароля. Личный дневник остаётся в браузере пользователя: приложение не отправляет записи и фотографии на сервер. На разных устройствах будут отдельные данные. Данные с localhost автоматически на опубликованный сайт не переносятся. Для загрузки сайта нужен интернет; полноценная автономная работа не реализована.

Альтернатива: содержимое `dist` после `npm run build` можно разместить на любом статическом хостинге. Относительные пути ресурсов уже настроены. Не открывайте `dist/index.html` двойным щелчком: используйте HTTP-хостинг.

## Как восстановить резервную копию

1. Внизу страницы нажмите **«Восстановить из файла»**.
2. Выберите ранее скачанный `iron-hook-backup.json` (до 10 МБ). Подходят и копии из первой версии.
3. Проверьте количество рыбалок, приманок, снастей и комплектов в окне подтверждения.
4. При необходимости нажмите **«Скачать текущую копию»**, чтобы сохранить нынешние записи.
5. Нажмите **«Заменить данные и восстановить»**. Все текущие записи будут заменены, а не объединены с копией.

До подтверждения данные не меняются; кнопка «Отмена» отменяет импорт. Некорректный или слишком большой файл отклоняется. При ошибке записи в хранилище текущие данные сохраняются, а окно остаётся открытым. Фото включены в копию. Восстановление выполняется локально, без отправки файла на сервер.

## Встроенная библиотека приманок

В разделе «Приманки» добавлена отдельная вкладка библиотеки с поиском, фильтрами и переносом выбранного варианта в форму личного каталога. Перед сохранением можно уточнить характеристики. Совпадающие нетестовые варианты помечаются как уже добавленные. Импортированные приманки входят в обычную резервную копию.

Файл `public/lure-library.json` поставляется вместе с приложением: **1 571 проверенный вариант** (модель + вес + расцветка): 88 с Onlyspin, 1 254 с Jpsnasti, 199 с Japan4you и 30 с Baita, проверка 2026-10-26. Это стартовая подборка из выбранных страниц и серий четырёх магазинов, не весь их ассортимент. Библиотека показывает по 24 карточки на страницу; поиск и фильтры работают по всей подборке и возвращают на первую страницу. Мягкие приманки исключены; вес каждого варианта подтверждён характеристиками карточки или точным названием варианта с граммами и не превышает 5 г (5 г включено). В библиотеке есть фильтры по производителю, типу, весу и источнику. Ограничение веса относится к библиотеке; личный каталог не меняется.

Если в магазине указан только код расцветки, он сохраняется в полях цвета и кода без выдуманного названия цвета. Для 1 483 вариантов добавлены внешние ссылки на фотографии конкретных расцветок с сайтов магазинов. Фотографии не копируются на сервер приложения; они загружаются при просмотре карточки. Если магазин удалит фото или запретит его загрузку, появится заглушка. В резервную копию попадает ссылка, а не само внешнее изображение. Собственное загруженное фото сохраняется внутри копии, как раньше. Ссылка ведёт на конкретную карточку товара. Цены и наличие не отслеживаются.

Второй источник — https://www.jpsnasti.ru/primanki (без «a»). Для вариантов Jpsnasti вес и код расцветки взяты из точных названий вариантов в сериях, производитель — из метаданных тех же карточек. У каждой записи ссылка на конкретный вариант, не общую серию. Представлены Nories, ValkeIN, Yarie, Velvet Arts, Naburaya и Rodio Craft.

Само приложение работает без запросов к магазинам. Сборщики `scripts/collect-onlyspin.py` и `scripts/collect-jpsnasti.py` обновляют ограниченные подборки, сохраняя записи другого источника. Отчёты `scripts/onlyspin-report.json` и `scripts/jpsnasti-report.json` фиксируют источники и причины исключения. Для запуска сборщиков нужны Python и зависимости из `scripts/requirements-library.txt`; для обычной работы сайта Python не требуется. Сборщики используют до двух запросов одновременно и сохраняют HTML в `/tmp` только на текущий день для повторных проверок. Перед публикацией обновлённого набора выполните сборку и тесты.

Формат карточки: `lure` (обычная приманка с уникальным ID), `source` (`Onlyspin` / `Japsnasti` / `Japan4you` / `Baita`), `url` (HTTPS-ссылка на конкретную карточку соответствующего магазина), `checkedAt` (дата проверки YYYY-MM-DD). Публиковать только проверенные сочетания модели, веса и расцветки. Не подставлять предполагаемые характеристики. Цены и остатки не копируются. Библиотека поставляется вместе с приложением; браузер обращается к магазинам только за внешними фотографиями при просмотре карточек.

## Категории и фотографии

Библиотека разделена на **блёсны, воблеры, кренки, цикады, вибы и раттлины**. Кренки — отдельный раздел для явно обозначенных магазином Crank/крэнк/кренк. Вибы и раттлины часто означают схожие приманки; в этом приложении они разделяются по обозначению источника, без выдуманного технического различия. Старые личные записи автоматически не переклассифицируются: изменить категорию можно в форме приманки. Фильтр по категориям есть также в личном каталоге.

`scripts/collect-extra-shops.py` собирает ограниченную подборку Japan4you и Baita. Он использует вес из характеристик, а не цифры из названия или URL. У Japan4you берётся только основной переключатель расцветок; варианты из блока рекомендаций исключены. Карточки без подтверждённых обязательных полей пропускаются. Дополнительные проверки парсера: `PYTHONPATH=/tmp/iron-parser:scripts python3 -m unittest discover -s scripts -p 'test_*.py'` (путь зависит от места установки beautifulsoup4). Отчёт — `scripts/extra-shops-report.json`.

Изображения принимаются только как JPEG/PNG/WebP: локальные data-изображения или HTTPS-адреса известных магазинов. Ссылки на сторонние домены и исполняемые схемы отклоняются при восстановлении копии. Для просмотра фотографий из магазинов нужен интернет; они не гарантированы для автономной работы.
